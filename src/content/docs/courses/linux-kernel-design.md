# Linux Kernel Design 笔记

> 这门课讲 Linux 内核的设计思想。不是要背算法，而是通过实现细节理解底层的运行逻辑——为什么这样设计、为什么这么组织。重点是建立对操作系统内核的整体认知框架。

---

## 一、为什么学内核

内核是用户程序和硬件之间的桥梁，提供**系统运行时最基本的功能**——文件系统怎么管理、多个程序怎么同时运行、内存怎么分配。

学内核不是要会写内核代码，而是：
- 理解操作系统是怎么工作的
- 知道一个程序从启动到运行到底经历了什么
- 透过 API 看到背后的设计取舍

---

## 二、内核的组织方式

### 设计原则
- **模块化**：进程控制、文件系统、存储管理、调度等各自独立，通过接口协作
- **分层结构**：底层接口，上层调用
- **软件复用**：操作系统的基本功能被反复使用，不重复造轮子

### 核心模块
| 模块 | 职责 |
|:---|:---|
| 进程控制 | 进程创建、调度、通信、终止 |
| 文件系统 | 文件的存储、读写、权限 |
| 存储管理 | 内存分配与回收 |
| 进程调度 | CPU 时间片分配 |
| 中断处理 | 硬件事件响应 |

每个模块独立开发、独立演进，但对外提供一致的接口。

---

## 三、进程：程序运行的实例

### 基本概念
进程是程序运行的一个实例。同一个程序可以创建多个进程，每个进程有**独立的地址空间**。

### 进程的运行状态
```
创建 → 运行 → 等待 → 运行 → 终止
        ↑       ↓
        ←───────┘
```
- **运行**：占用 CPU 执行指令
- **等待**：等待 I/O 完成或某个事件
- **终止**：正常结束或被信号杀死

### 进程与 I/O
进程的标准输出默认是屏幕，但可以通过**重定向**或**管道**连接到别处：

```bash
ls > output.txt          # 重定向到文件
ls | grep ".txt"         # 管道连接到下一个进程
```

---

## 四、进程间通信（IPC）

多进程同时运行时，需要交换数据。内核提供了几种方式：

### 1. 管道（Pipe）
最基础的 IPC。A 进程的标准输出 → 管道 → B 进程的标准输入：

```bash
# 单向流式数据传递
ps aux | grep python | wc -l
```

### 2. 信号（Signal）
进程间的事件通知。不是传数据，是"通知发生了某件事"：

```c
kill(pid, SIGTERM);   // 终止进程
kill(pid, SIGKILL);   // 强制杀死
```

### 3. 共享内存（Shared Memory）
进程间共享同一片内存区域，速度最快但需要同步机制保护。

### 4. 其他方式
- **套接字**：跨机器通信
- **消息队列**：发送消息给指定进程
- **信号量**：协调进程间的同步

---

## 五、文件系统

文件系统是用户和磁盘之间的抽象层。用户用文件名访问数据，不需要关心物理存储位置。

内核负责：
- 把逻辑文件名映射到磁盘位置
- 管理权限（读/写/执行）
- 维护元数据（大小、时间戳、所有者）
- 提供统一的 I/O 接口（read/write/lseek）

---

## 六、内存与缓冲区管理

这是内核最核心的部分之一。程序运行时用的内存有限，磁盘 I/O 又慢，所以必须用**缓冲池**在内存和磁盘之间做中间层。

### 缓冲池的两个核心原则

**原则一：局部性原理**
> 把当前使用的数据尽量长时间地保留在内存中。下次还需要时能快速找到，减少磁盘访问。

**原则二：LRU 替换**
> 缓冲区满了又要分配时，把**最长时间没被使用**的缓冲区换出去——用得越早的数据再次被使用的可能性越小。

### 缓冲池的工作流程
```
进程读磁盘
    ↓
检查缓冲池中是否已有该数据块
    ↓ 有 → 直接用（内存命中，快）
    ↓ 无 → 分配一个缓冲区
    ↓
    ↓ 缓冲区已满 → LRU 选出最久未使用的，替换掉
    ↓
从磁盘读入数据块到缓冲区
    ↓
进程使用数据
```

### 缓冲池大小
通常用**相当大比例的物理内存**作为缓冲池，越大命中率越高，但占用也越多。

### 磁盘调度
当进程要读磁盘时，系统需要决定用哪个缓冲区存放读取的数据。如果缓冲池已有该数据块，直接返回；否则按磁盘调度策略读取（比如电梯算法，按磁头移动方向顺序读取，减少寻道时间）。

## 七、核心设计思想小结

| 思想 | 含义 | 解决什么 |
|:---|:---|:---|
| **模块化** | 各模块独立，通过接口协作 | 可维护、可演进 |
| **分层** | 底层接口，上层调用 | 职责分离 |
| **局部性原理** | 数据访问有规律，用缓存利用 | 减少磁盘 I/O |
| **LRU 替换** | 淘汰最不可能再被访问的 | 缓存满时最优策略 |
| **缓冲池** | 内存与磁盘之间的中间层 | 平衡速度 vs 成本 |

---

## 思考

1. 局部性原理为什么成立？程序访问数据通常有什么规律？
2. LRU 是最优策略吗？在什么情况下会失效？
3. 缓冲池越大越好吗？有什么副作用？
4. 管道只能单向传递数据，如果想双向通信该怎么做？

<font color=Red>注意：课程目标是理解"为什么这样设计"，不是记住"怎么实现"</font>
